# Brainstorm

Apply section 1 of the [workflow](../../../docs/WORKFLOW.md). Use the
user's request or an existing task record. Read the README and relevant
code to understand the context before proposing an approach.

1. Identify the problem, goal, scope, and observable outcome.
2. Separate verified facts from assumptions and open questions. Inspect
   the project first; ask the user only when the answer materially affects
   the approach or correctness.
3. Compare alternatives where there are meaningful tradeoffs. Recommend
   an approach and explain why.
4. Write verifiable acceptance criteria covering the main behavior and
   relevant edge cases. Record risks and remaining blockers to planning.

Update the Brainstorm section of an existing task record, or present the
results briefly in the conversation. The output must let Plan proceed
without guessing the requirements again.

When invoked independently, end after analysis and recommendations. Edit
code or continue to another step only when the user's request includes
that work.
